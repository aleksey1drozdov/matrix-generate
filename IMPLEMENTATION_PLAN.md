### План реализации приложения: Гамильтоновы пути

#### Фаза 1: Проектирование и структура данных
1. **Базовые классы:**
   - `Config`: Парсер `config.ini`.
   - `Point`: Структура с координатами `(x, y)`.
   - `Grid`: Класс для хранения состояния сетки (посещенные/непосещенные узлы).
   - `Path`: Контейнер для хранения последовательности точек.
2. **Система координат:**
   - Реализовать преобразования (H, V, M, T) как функции, принимающие `Point` или `Path` и возвращающие новый объект.

#### Фаза 2: Ядро алгоритма (Backtracking)
1. Реализовать рекурсивный DFS с поддержкой:
   - Битовых масок (bitmasking) для хранения состояния сетки.
   - Оптимизации "тупиков" (подсчет свободных соседей у каждого узла).
   - Шахматной раскраски (отсечение стартовых точек в нечетных сетках).
   - Сбора всех найденных путей в список (или записи сразу в файл для экономии памяти).

#### Фаза 3: Симметрия и оптимизация
1. Реализовать функцию `IsInSearchZone(Point start)`, проверяющую попадание в 1/8 часть сетки.
2. Реализовать генератор симметричных точек: для каждой точки в зоне поиска вычислить все ее симметричные отображения и доступные преобразования.
3. Добавить логику сопоставления преобразований (H, V, M, T) к именам файлов для автоматического формирования полных данных по сетке без дублирования самих путей в теле файла.

#### Фаза 4: Работа с файловой системой
1. Реализовать `FileHandler`:
   - Создание структуры `maps/NxN/`.
   - Формирование названий файлов согласно ТЗ (`0-1_H_V_M_N`).
   - Потоковая запись путей в текстовые файлы.
   - Очистка/перезапись папок при старте новой генерации.

#### Фаза 5: Многопоточность и Управление потоками
1. Реализовать `WorkerPool` с поддержкой рекурсивного разложения:
   - Добавить параметр `recursion_depth_parallelism` в `config.ini`.
   - На каждом шаге рекурсии проверять наличие свободных потоков в пуле: если есть, "отпочковывать" задачу ветвления в пул, даже если $K$ превышена.
   - Реализовать `ThreadSafeFileLogger` для синхронизированной записи путей в файлы.
2. Использование `std::atomic<long long>` для подсчета общего количества путей.
3. Реализовать механизм финализации:
   - После завершения всех потоков переименовать директорию `NxN` в `NxN(TotalCount)`.

#### Фаза 6: Пользовательский интерфейс и Валидация
1. Реализовать CLI-интерфейс:
   - Запрос размерности $N$.
   - Проверка $N > 1$.
   - Индикация прогресса (сколько точек из зоны поиска обработано).
2. Реализовать валидатор стартовых точек:
   - Проверка попадания в разрешенный цвет (для нечетных).
   - Информационное сообщение при попытке запуска из точки вне зоны поиска.

#### Фаза 7: Тестирование и верификация
1. Проверка на малых сетках (2x2, 3x3) вручную.
2. Сравнение количества найденных путей с известными данными из OEIS и таблицы в `ham_chains_v1.pdf` (например, для 12x12).
3. Проверка корректности применения всех симметрий.
4. Верификация утверждения $C_0 = 0$ для нечетных $N$.
5. Тестирование производительности при разном количестве потоков.
