### Техническое задание: Генератор гамильтоновых путей на квадратной сетке

#### 1. Общее описание
Приложение предназначено для генерации всех возможных нециклических гамильтоновых путей (walks) и потенциально гамильтоновых циклов (circuits) в квадратной сетке размером $N \times N$. 

Основной акцент сделан на объединении двух подходов:
1. **Генерация (DFS с возвратом):** Используется для вывода каждого конкретного пути в файл (согласно `APP_DESCRIPTIONS`).
2. **Оптимизация из научной статьи (`ham_chains_v1.pdf`):** Применение битовых масок (bitmasking) для мгновенной проверки посещенных узлов, использование симметрии 1/8 и шахматной раскраски для отсечения невозможных ветвей поиска.

#### 2. Глоссарий (на основе ham_chains_v1.pdf и APP_DESCRIPTIONS)
- **Сетка ($N \times N$):** Квадратное поле из $N^2$ узлов.
- **Гамильтонов путь (Hamiltonian walk, k=1):** Открытая последовательность из $N^2$ уникальных узлов, где каждый последующий узел является соседом предыдущего. Имеет две различные оконечности (начало и конец).
- **Гамильтонов цикл (Hamiltonian circuit, k=0):** Замкнутый путь, проходящий через все узлы ровно один раз. Существует только для четных $N \times N$ (L четно).
- **Гамильтонова цепь порядка k (Hamiltonian chain):** Набор из $k$ непересекающихся путей, которые вместе посещают все узлы сетки. В текущей реализации фокус на $k=1$.
- **Точка старта ($x, y$):** Узел, с которого начинается поиск пути. Координаты от $0$ до $N-1$.
- **Шахматная раскраска:** Разделение узлов на два цвета (бипартийный граф). В нечетных сетках количество узлов одного цвета на 1 больше. Путь возможен только из "мажоритарного" цвета. Циклы ($C_0$) невозможны в нечетных сетках.
- **Зона поиска (1/8):** Минимальный треугольник сетки, пути из которого через преобразования симметрии позволяют восстановить пути изо всех остальных точек сетки.

#### 3. Алгоритм генерации
**Основной метод: Оптимизированный поиск в глубину (DFS) с битовыми масками.**

В статье `ham_chains_v1.pdf` описан алгоритм перечислительной матрицы (Transfer Matrix) для *подсчета* путей. Однако для *генерации и записи* каждого пути (как требует ТЗ) используется DFS, дополненный техниками из статьи:

1. **Битовые маски (Bitmasking):**
   - Состояние сетки хранится не в массиве, а в 64-битном или 128-битном целом числе (для сеток до 8x8 или 11x11 соответственно).
   - Проверка `isVisited` и пометка `setVisited` выполняется за $O(1)$ через побитовые операции `&` и `|`.
   
2. **Инициализация:** Пометить стартовую точку в битовой маске. Добавить в текущий путь.

3. **Рекурсивный шаг:**
   - Для текущего узла найти всех непосещенных соседей.
   - **Оптимизация "Тупиков" (Pruning):** Если у любого непосещенного узла (кроме конечного) осталось менее 2 свободных соседей, этот путь не может быть гамильтоновым (кроме случая завершения). Это значительно сокращает дерево поиска (техника, упоминаемая в контексте эффективных перечислителей).
   - Для каждого соседа:
     - Обновить битовую маску.
     - Добавить соседа в путь.
     - Если длина пути равна $N^2$:
       - Сохранить путь.
       - Детекция цикла: если последний узел сосед с первым.
     - Иначе, вызвать рекурсию.
     - **Backtrack:** Сбросить бит в маске.

4. **Оптимизация (Шахматная раскраска):**
   - Если $N$ нечетно:
     - Сумма координат $(x+y)$ определяет цвет узла.
     - Если $(x+y)$ четно (цвет 0) и их в сетке больше, чем цвета 1, старт разрешен.
     - Если $(x+y)$ нечетно (цвет 1) и их меньше, поиск не запускается.
   - **Важно:** В нечетных сетках $N \times N$ количество циклов $C_0 = 0$ (математический факт из `ham_chains_v1.pdf`).

#### 4. Оптимизация симметрии
Для минимизации вычислений поиск запускается только для точек $(x, y)$, находящихся в "основном треугольнике" (1/8 сетки):
- Условие зоны: $0 \le x \le \lfloor(N-1)/2\rfloor$ и $x \le y \le \lfloor(N-1)/2\rfloor$.
- Все пути из других точек получаются применением преобразований к найденным путям:
  - **H (Horizontal):** $(x, y) \to (x, N-1-y)$
  - **V (Vertical):** $(x, y) \to (N-1-x, y)$
  - **M (Mirror/Rotation 180°):** $(x, y) \to (N-1-x, N-1-y)$
  - **T (Transpose):** $(x, y) \to (y, x)$
  - И их комбинации (например, $HT, VT$).

#### 5. Требования к выводу и хранению
- **Конфигурация (config.ini):**
  - `threads_count`: Целое число (по умолчанию 1 или количество ядер CPU).
  - `recursion_depth_parallelism`: Глубина рекурсии для параллелизма.
  - `write_standard`: (true/false) записывать ли стандартный формат.
  - `write_semicolon`: (true/false) записывать ли формат с точкой с запятой.
  - `write_simplified`: (true/false) записывать ли упрощенный формат.
- **Структура директорий:** `maps/NxN(TotalCount)/`
- **Именование файлов:** `x-y_СИММЕТРИИ.txt` (например, `0-1_H_V_M_T_N.txt`).
- **Запрет дублирования:** В файлы записываются **только оригинальные пути**, найденные в зоне поиска 1/8. Симметричные пути (полученные через H, V, M, T) физически в файлы НЕ записываются для экономии места.
- **Интерпретация симметрий:** Список симметрий в названии файла (`_H_V_M_T`) указывает, какие преобразования следует применить к каждому пути из этого файла, чтобы получить все возможные пути для этой и симметричных ей точек старта.
- **Форматы вывода:**
  1. **Стандарт:** `maps/NxN(Count)/`, формат `x1,y1,x2,y2,...,x(N^2),y(N^2)`.
  2. **Точка с запятой:** `maps/NxN_semicolumn(Count)/`, формат `x1,y1;x2,y2;...,x(N*N),y(N*N);`.
  3. **Упрощенный:** `maps/NxN_simplified(Count)/`, формат `p1,p2,...pN*N`, где $p_i$ — порядковый номер ячейки ($y \times N + x + 1$).
- **Перезапись:** При каждом запуске для конкретной размерности файлы в соответствующих папках должны обновляться.

#### 6. Интерфейс и валидация
- Ввод пользователем числа $N > 1$.
- Проверка стартовой точки на валидность (цвет в нечетной сетке).
- Если выбранная точка вне зоны поиска, программа должна вывести: "Точка вне зоны поиска. См. файл [имя_файла_симметричной_точки]".

#### 7. Многопоточность
- **Модель:** Адаптивное рекурсивное разложение задач (Adaptive Task Decomposition).
- **Разделение задач:** 
  1. Стартовая точка $(x, y)$ из зоны поиска отправляется в пул задач.
  2. Внутри рекурсии на каждом шаге (ветвлении) проверяется текущая загрузка пула потоков.
  3. Новая задача в пуле создается (с обязательным **копированием текущего состояния**: битовой маски и пути), если:
     - Текущая глубина рекурсии меньше базового порога $K$ (гарантированное наполнение пула).
     - **ИЛИ** в пуле есть свободные потоки (idle threads) в данный момент.
  4. Если все потоки заняты и глубина больше $K$, поиск продолжается в текущем потоке (передача состояния по ссылке/backtracking). 
  5. Это позволяет динамически дозагружать освободившиеся ядра даже на большой глубине дерева поиска.
- **Синхронизация:** 
  - **Файловый ввод-вывод:** Использование `ThreadSafeFileLogger` (MPSC Queue или Mutex).
  - **Глобальный счетчик путей:** `std::atomic<long long>` для `TotalCount`.
